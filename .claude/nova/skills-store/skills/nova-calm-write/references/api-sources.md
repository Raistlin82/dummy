# Fonti delle API di SAP Cloud ALM: cosa è verificato e cosa no

Verificato il 2026-09-30 con il server MCP SAP Docs (SAP Help Portal, *API Guide for SAP Cloud ALM*), i notebook ufficiali di `SAP-samples/cloud-alm-api-examples` (commit `5f01191`, Apache-2.0) e il codice di `consetto/calmcp` v0.9.2 (pin portato a v1.0.0 il 2026-11-11: stessi strumenti, cambiano solo i nomi della paginazione `top`/`skip`, `rest_filters` e `with_count`). Prima di usare un'API in uno sviluppo, rileggi la sua pagina: SAP le aggiorna (l'ultima modifica degli stati delle feature è di gennaio 2026).

Riletto e completato il 2026-11-12 (track W6, ciclo di vita completo in Cloud ALM) con il server MCP SAP Docs sulle pagine SAP Help indicate sotto.

## Non verificato o non disponibile: passo manuale

| Cosa | Perché | Cosa fai |
|---|---|---|
| Inviare da CI gli esiti dei test automatici a Cloud ALM | Nessuna API di push documentata: la Test Automation API la implementa il tool, e Cloud ALM *legge* gli esiti dal tool. I test run e i risultati dei test manuali non hanno endpoint di scrittura documentati. | Allega l'evidenza: `ci-evidence` aggiunge alla feature (e al test case) un riferimento URL al run di CI con il conteggio. L'esecuzione in Cloud ALM (Test Execution) resta manuale, oppure passa da un tool di test automation già integrato (per esempio Tricentis, UiPath, Panaya). |
| Stato *Ready for Production* e *Deployed* | Il primo si approva nell'app Features; il secondo è effetto del deployment. | Non li imposti: sono evidenza di `GO_LIVE_APPROVAL` e `IMPORT_PROD`. |
| Assegnare trasporti o richieste di cTMS alla feature | Nella Features API trasporti e riferimenti ai trasporti sono in sola lettura. | Dalla feature nell'app, da chi ha il ruolo; Nova ARC-1 e cTMS creano i veicoli. |
| Registrazione in Landscape Management, casi d'uso di monitoraggio, allarmi e notifiche | Nessuna API pubblica. | Prepari la lista per l'amministratore di Cloud ALM (`operations-handover.md`). |
| Corpo di `POST /TaskAssignments` della Test Cases API (test case ↔ requisito o user story) | La pagina SAP (rilettura del 2026-11-12) elenca l'endpoint ma non il corpo; la specifica sul SAP Business Accelerator Hub richiede il login. Il corpo di `POST /tasks/{taskId}/relations` invece è ora documentato (`type`, `relationTaskId`). | Leggi la specifica `CALM_TM` con il login dell'utente, scrivi il corpo in un file e usa `request`; oppure fai il legame nell'app. |
| Creare fasi, sprint, release o progetti | La Project API lo consente, ma con lo scope `calm-api.projects.write`, che modifica anche i progetti. | Li crea il project lead nell'app *Projects and Setup*; NOVA li legge. |
| Header `X-Calm-Notification` | Documentato nelle pagine *Resource Changes* (2026-11-12): con `true` una scrittura via API manda l'evento alle sottoscrizioni del tenant (Jira, ServiceNow, workflow). | Non lo usi: le scritture di NOVA non devono far partire integrazioni del cliente senza che lui lo decida. |
